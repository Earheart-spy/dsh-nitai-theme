# 配置项自检报告

这份报告记录「个性化配置」里每一项到底有没有真的画到界面元素上。检查方式不是肉眼看截图，而是在真实页面里把该元素的三档样式依次写进配置、刷新注入的样式表，再读回目标元素的计算样式（`box-shadow`），与预期值比对。

自检脚本是 `tools/audit-surfaces.js`，通过插件的调试路由 `/dsh-nitai-theme/_audit.js` 加载，调用方式：

```js
await window.__ntAudit()            // 默认跑 raised-md / inset-md / flat 三档
await window.__ntAudit(['raised-lg', 'inset-lg'])   // 指定档位
```

判定口径：`raised-sm` 应出现 `5px 5px 12px` 且不含 `inset`；`raised-md` 是 `9px 9px 21px`；`raised-lg` 是 `18px 18px 42px`；`inset-sm` 是 `2px 2px 4px` 且含 `inset`；`inset-md` 是 `3px 3px 7px`；`flat` 必须是 `none`。

> 2026-11-17 更新：清单里删掉了三项——「输入区 · 附件预览卡」「主按钮（确定 / 添加插件等）」「浮层 · 工具提示 / 轻提示」。原因是这三处的底色本身不由主题控制（附件卡用原生 input-major 背景、工具栏按钮是浅色小方块、工具提示是深色气泡），套上新拟态的阴影后反而更难看。清单因此从 36 项变成 33 项，本文下面的记录保留当初验证时的状态，供需要时追溯。

## 三、验证方式说明与遗留

- 值都是运行时读出来的：把配置写进去 → 重新拉取 `/dsh-nitai-theme/theme.css` → 替换 `<style id="nitai-theme-css">` 的内容 → 等 260ms（主题有 0.18s 过渡）→ 读 `getComputedStyle(el).boxShadow`。
- 会话正文那几项（气泡、代码块、表格、差异视图、工具卡）需要会话里真的有这些内容才会出现；这一轮是在一个有代码块和表格的会话里跑完的。
- 工具提示要靠鼠标真实悬停才会挂载，自动化里用「注入同结构元素 + 核对 DSH 样式表里的选择器」两步代替，没有做人工悬停截图。
- 这一轮无法验证的只有已经从清单里删掉的两项（任务面板、任务项），原因是当前 DSH 版本界面里不存在对应元素。

## 四、悬停 / 按下 / 选中三档的规则检查

计算样式只能读「当前这一瞬间」的值，没法模拟鼠标悬停，所以另外做了一次规则文本检查：把每一项的 常态 / 悬停 / 选中 设成三个不同档位（凸起·中 / 凸起·小 / 内凹·深），重新生成样式表，确认三档各自都写出了独立规则。

结论：全部 36 项都写出了三条规则，包括五个「选中」靠属性或类名而不是 `:active` 的项：

| 配置项 | 选中态怎么判定 | 规则是否写出 |
| --- | --- | --- |
| 侧栏 · 导航行 | `[class~="wtg9ga_panelRow"][aria-current="page"]` | 是 |
| 侧栏 · 会话行 | `[class~="wnFoaW_sessionRow"][aria-selected="true"]` | 是 |
| 侧栏 · 工作区行 | `[class~="wnFoaW_projectRow"][aria-expanded="true"]` | 是 |
| 会话头部 · 单个标签 | `[class~="an3WzG_tabActive"]` | 是 |
| 浮层 · 菜单项 | `[role="menuitem"]:focus-visible` | 是 |

这一项检查专门针对之前踩过的坑：导航的「选中」曾经被翻译成 CSS `:active`（只在按住鼠标那一刻成立），导致「点了之后没有任何变化」。

## 五、两个元素的专属处理（2026-11-17 补）

用户实测发现两处「配置写了但看不出效果」，原因不是配置没生效，而是元素形状让阴影表现不出来：

| 元素 | 现象 | 原因 | 处理 |
| --- | --- | --- | --- |
| 会话头部 · 整条容器 | 选「凸起」看不出变化，「内凹」「描边」都很清楚 | 头部是通栏、又贴着窗口顶边，上左右三面的外阴影全被裁掉；`18px 18px 42px` 铺开六十多像素，落在浅灰画布上只剩一层薄雾 | 这一项改成专属阴影：顶部一道白色高光 + 底部一道暗色细线 + 收窄的下方投影，并抬到 `z-index: 3`，让下沿阴影不被消息区盖住。像素测量：修复前下沿 45px 处只比背景暗 12 级，修复后暗 24 级且 60px 内收干净 |
| 会话头部 · 标签条容器 / 单个标签 | 凹槽比标签矮，字像要溢出；悬停和选中的胶囊大小不一致 | DSH 给标签加了负外边距 `margin: -10px -10px 0`（扩大点击热区），凹槽按盒子高度算就矮一截；选中态又额外加 `4px 11px` 内边距，一换状态盒子就变形 | 标签统一 `padding: 5px 12px`、`margin: 0`，凹槽补 `2px` 内边距并垂直居中；悬停只换底色不加投影（相邻标签只隔 6px，两团凸起阴影会叠成暗带） |

自检脚本也补了对应能力：`surfaces.json?debug=1` 会带出 `shadow` 字段，`__ntAudit` 对带专属阴影的项改成「样式表里有这一档 + 元素上确实有阴影」两步核对，不再拿公共档位的数值去比。

### 差异行左侧的红绿色条（2026-11-17 补）

聊天消息和文件预览弹窗里的 ```diff 代码块，每一行左边原本有一条 3px 的红/绿色条。它来自 markdown 代码块渲染器自己的样式：`_diffAdd_` / `_diffDel_` 上写着 `box-shadow: inset 3px 0 0`，而每行又有 `padding: 0 16px`，色条正好压在这段留白上，行与行之间还接不齐，看起来像贴在纸边的标签。

处理办法是去掉色条、只保留很淡的行底色，增删含义交给行首的 `+` / `−` 符号颜色：

```css
[class*="_diffAdd_"],
[class*="_diffDel_"] {
  box-shadow: none !important;
  border-radius: 4px !important;
}
```

这和文件差异视图（`_0cITKW_` 那一套）的处理保持一致：那套也去掉了 `inset 3px 0 0` 色条，只留柔和的整行底色。

### 「一部分圆角、一部分直角」（2026-11-17 补）

用户给「正文 · 工具调用 / 思考块」这一项设了悬停效果后，发现有的地方是圆角、有的地方是直角。原因是这一项同时管三类元素，而它们的原生形状并不一样：

| 元素 | 类名 | 原生圆角 |
| --- | --- | --- |
| 工具调用行 | `pDft-q_callRow` | 8px（DSH 自己写了 `border-radius: var(--dsw-radius-sm)`） |
| 思考块 | `VJlF5q_root` | 无 |
| 上下文注入块 | `iFrn8G_root` | 无 |

阴影是沿元素盒子画的，后两类没有圆角，一加阴影就露出方角。处理办法是给清单项加一个 `radius` 字段，配置生效时把圆角一起写进去：

```js
{
  id: 'tool-card',
  selector: '[class*="pDft-q_callRow"], [class*="VJlF5q_root"], [class*="iFrn8G_root"]',
  radius: '12px',
  …
}
```

生成的 CSS 因此在阴影那条规则之后多一条：

```css
body:not(#nt-config-noop) [class*="pDft-q_callRow"],
body:not(#nt-config-noop) [class*="VJlF5q_root"],
body:not(#nt-config-noop) [class*="iFrn8G_root"] { border-radius: 12px !important; }
```

同一轮里按同样标准核对了清单中的其他项，把原生没有圆角的都补上：`msg-actions`（消息悬停操作条）10px、`inline-code`（行内代码）6px、`diff-view`（差异视图）10px、`rightbar-tabs`（右栏标签）8px、`tool-entry`（右栏工具卡）12px。已经在主题里有圆角的（`pre` 14px、表格 14px、弹窗 24px、菜单 18px、菜单项 12px、附件卡 20px、提示气泡 12px）不再重复指定。

## 六、如何复跑

1. 用隔离的 `DSH_HOME` 起一个 web 实例：`DSH_HOME=…\.dsh-home dsh web --port 0 --no-open`。
2. 打开页面后注入自检脚本：`<script src="/dsh-nitai-theme/_audit.js">`。
3. 控制台执行 `await window.__ntAudit()`，返回每项的 `{id, detail}`；`detail` 里出现 `no-element` 表示当前界面没有那个元素（需要先打开对应界面），`fail:` 开头表示规则没落到元素上。

## 八、默认外观与一键恢复（2026-11-17 补）

默认外观不是一份预填的配置，而是直接固化在 `lib/theme.css` 末尾的「元素默认凹凸（主题自带外观）」一段里（38 条规则，选择器统一带 `body:not(#nt-config-noop)` 前缀以压过前面的通配规则）。`lib/surfaces.js` 里的 `DEFAULT_CONFIG` 是空的，所以配置面板默认每一项都是「跟随主题默认」、勾选框全空。

验证方式与结果：

- **空配置 = 调好的效果**：清空 `config.json` 后，逐项读计算样式——`new-session` 是 `5px 5px 12px`（凸起·小）、`nav-row`/`composer`/`notch` 是 `2px 2px 4px inset`（内凹·浅）、`send-button` 是 `9px 9px 21px`（凸起·中），与作者调好的取值一致。
- **等价性对照**：先测空配置下的计算值，再 POST 一份这 19 项的显式配置、刷新样式表后重测，7 个抽样元素（新会话、导航行、账户卡、输入卡、发送按钮、刘海、统计槽）前后 `box-shadow` 字符串完全相同。
- **面板初始态**：33 行、59 个下拉全部为空（跟随主题默认）、33 个勾选框全未勾选。
- **默认档位标注**：`lib/surfaces.js` 的 `THEME_DEFAULTS` 记下每个状态实际用的档位（19 个元素、34 个状态），宿主通过 `/dsh-nitai-theme/surfaces.json` 的 `defaults` 字段下发给面板，面板把「跟随主题默认」显示成「跟随主题默认（内凹 · 浅）」这样的文字。实测：`nav-row` 三个状态下拉的首项分别是「跟随主题默认（内凹 · 浅）」「（凸起 · 小）」「（凸起 · 中）」，没有单独写样式的项（例如 `hover-card`、`dialog`）只显示「跟随主题默认」。
- **两处不会走偏**：`tools/check-theme.mjs` 会逐条核对 `THEME_DEFAULTS` 里的档位在 `theme.css` 里确实写着对应的 `box-shadow` 变量，当前 34 处全部对得上；两处一旦不一致，自检直接失败。
- **一键恢复**：把 `notch` 常态改成「凸起·大」保存（计算值变成 `18px 18px`），再点「恢复默认配置」，接口 `DELETE /dsh-nitai-theme/config.json` 返回 `ok: true`，下拉回到空值、计算值回到 `2px 2px inset`。
